# Release Checklist

A small single-page application for creating releases, tracking a fixed release checklist, and automatically calculating release status.

## Stack

- React, Vite, and Tailwind CSS
- Node.js and Express
- PostgreSQL hosted by Supabase
- Prisma ORM

## Local setup

Requirements: Node.js 24 and a Supabase PostgreSQL project.

1. Install dependencies:

   ```bash
   npm install --prefix client
   npm install --prefix server
   ```

2. Copy `server/.env.example` to `server/.env` and replace `DATABASE_URL` with the Supabase Session pooler connection string from **Connect** in the Supabase dashboard.

3. Apply the database migration and generate Prisma Client:

   ```bash
   npm run prisma:deploy --prefix server
   npm run prisma:generate --prefix server
   ```

4. Start the API and frontend in separate terminals:

   ```bash
   npm run dev --prefix server
   npm run dev --prefix client
   ```

The frontend runs at `http://localhost:5173` and the API at `http://localhost:3000`.

## Environment variables

### Server

- `DATABASE_URL`: Supabase PostgreSQL connection string.
- `DIRECT_URL`: optional direct PostgreSQL connection for migrations.
- `PORT`: Express port; defaults to `3000`.

### Client

- `VITE_API_URL`: API server origin; defaults to `http://localhost:3000` in development. Production uses the current site origin.

## API endpoints

| Method | Endpoint | Purpose |
| --- | --- | --- |
| `GET` | `/api/health` | Check API availability |
| `GET` | `/api/releases` | List all releases |
| `GET` | `/api/releases/:id` | Get one release |
| `POST` | `/api/releases` | Create a release |
| `PATCH` | `/api/releases/:id` | Update additional information |
| `PATCH` | `/api/releases/:id/checklist` | Set one checklist step's completion state |

Status is calculated by the API and is never stored or manually selected.

## Database schema

The `releases` table contains:

| Column | Type | Description |
| --- | --- | --- |
| `id` | text | Primary key generated by Prisma |
| `name` | text | Required release name |
| `due_date` | timestamp | Required due date and time |
| `additional_info` | text, nullable | Optional release notes |
| `completed_steps` | text array | IDs of completed fixed checklist steps |
| `created_at` | timestamp | Creation time |
| `updated_at` | timestamp | Last update time |

## Deploy to Render

The root `render.yaml` deploys the API and built SPA as one Render web service.

1. Push this repository to GitHub.
2. In Render, select **New → Blueprint** and connect the repository.
3. Enter the Supabase Session pooler connection string when Render requests `DATABASE_URL`.
4. Deploy the Blueprint.

The build command installs both packages, generates Prisma Client, applies migrations, and builds the React application. Express serves both the SPA and API from the resulting Render URL.
